# Bank passbook scanning

- Passbook OCR uses bundled ML Kit through `PassbookScanner` on Android and lazy Tesseract in browsers; images stay local, camera cache is deleted, and no OCR result is stored or logged. Why: bank photos must not reach paid/cloud OCR or permanent app storage.
- `passbookText.ts` reads each field independently from passbooks, cheques and printed details (labels anywhere in a line, cheque signature-area names, visible bank names only, never from IFSC); unlabelled account numbers need cheque wording and skip MICR/cheque/branch/customer lines; damaged or conflicting values stay blank, several readings merge by majority (`mergePassbookReadings`). Bank Details and signup share `PassbookScanCard`, preserve manual values and clear confirmation after extraction; scans cannot overlap save/OTP or leave signup mid-scan. Existing workers use `submit_my_bank_details`, signup keeps `register_worker_v2` after phone verification. Why: OCR must never guess data, bypass manual confirmation or authorize verification/bookings/payouts.- Visible bank labels (badge, Home/Profile card, Bank Details text) come only from Admin's `bank_setup_status` parsed into `BankDetails.setup`; legacy `status`/`can_edit` decide only editing/locking. Unknown setup values reject the answer; missing ones fall back to legacy fields. Why: legacy status stays "pending" after Cashfree registration, so it cannot describe what workers see.
