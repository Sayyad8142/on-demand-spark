# Security patch drafts — proposals, not applied fixes
## 1. Worker-editable score/input fields
Targets: workers grants/policies, registration/profile RPCs, `sync-worker-profile`, supported name/photo/manual-UPI clients. Inventory live effective INSERT/UPDATE/upsert/table+column grants, permissive policies, views, trigger and RPC definitions first (not performed here). Table-wide UPDATE defeats column revocation. Replace broad mutation with verified Firebase-bound allowlisted server operations or narrow columns only after identity bridge proof. Deny client-controlled scores, ratings/counters, onboarding, fault/health/eligibility and finance inputs on INSERT and UPDATE. Existing guarded booking/OTP/payout mutations remain untouched. Preserve real supported profile payloads; `profileFieldsSafe` is a provisional example, not the actual migration allowlist. No guessed REVOKE against workers is drafted/executed before full inventory.

## 2. Authenticated telemetry + worker/offer binding
Backend target: `supabase/functions/ack-booking-delivery/index.ts`, shared Firebase verification helper, `src/lib/bookingAck.ts` explicit token transport (future changes only). Verify fresh Firebase ID token cryptographically using configured Admin SDK, project/audience/issuer/expiry; specify revoked/disabled-account policy. Header presence/public anon key/body ID/decoded JWT are NOT identity. Resolve workers.user_id by parameterized verified UID; UUID-shaped legacy workers.id fallback only with uniqueness/conflict check. Refuse ambiguous identity. Verify worker owns booking_request and request booking matches supplied booking. Event aliases and late owned-offer retry supported; accept bounded occurrence timestamps but never reopen withdrawn/settled offers. Validate method/body size/event allowlist, server offer generation, stable idempotency key. Append-only existing event uniqueness retained; new intervals stay separate.

Legacy ACKs must not contribute trusted evidence or update trusted health/request timestamps. A transitional diagnostic-only endpoint must quarantine legacy claims without declaring trusted success. Compatibility impact of ceasing old writes/watchdog behavior requires coordinated native testing and separate live approval. Do not switch the existing endpoint backend-only. Pure bindOffer tests use already verified mock actors; they DO NOT test cryptographic token validity or prove deployed security.

Adjacent untrusted source candidates: `worker-heartbeat`, `worker-keepalive-ack`, `report-missed-booking`. Their future hardening needs own rollout approval; until then exclude these body-identity claims from V4 evidence. No operational reachability/dispatch change now.

## 3. Leaderboard authentication
Target `supabase/functions/get-worker-leaderboard/index.ts`: remove token split/decode trust and arbitrary service-role preview fallback. Verify Firebase caller, bind exactly one worker, derive community server-side; no body admin flag/scope override. Guest response uses segregated synthetic data only. Current memory prohibits full names/PII: use approved public display alias, permitted photo and community-only minimal metrics; never contacts, addresses, OTP, UPI, tokens or private fault notes. Preserve existing response keys via versioned adapter, zero remains zero, null is explicit uncomputed, keep V2 authority until separate V4 display approval. Admin authority comes from established separate roles table/server validation, not client storage/profile fields or invented UID cast. Actual external admin identity bridge NOT VERIFIED.

## 4. Duplicate fault protection
Normalize refusal/cancel/reassign manifestations of one withdrawal to worker+booking+assignment-generation+canonical cause. Unique database constraint resolves concurrent producers; conflict => read same incident, append approved revision, no second subtraction. Faults change canonical R outcome only; no additive penalty, no same complaint in Q/A/O. Different generation/workers stay distinct. Unknown generation/causal overlap -> review, not invented matching. SQL drafts enforce business key; full producer/decision chain mapping and concurrent DB tests remain blocked.

## 5. ACK/timeout normalization
Keep raw writer/status/time/version and provenance. Accepted/rejected require authoritative confirmation; failed tap stays unresolved. timeout/timed_out -> lifecycle timeout, NOT blame. withdrawn/taken -> lost; unreachable/failed/unsent -> technical. Received/opened backfilled from acceptance = derived_from_server_response, never delivery latency. Neutral O/A locks remain even after normalization. Do not rename live statuses/modify triggers/health penalties as a side effect.

## Review-only implementation skeleton
CORS → shape validation → verify Firebase (not decode) → resolve unique worker → ownership/generation → event allowlist/timing → idempotent append → minimal result. Service client is constructed/used only after authorization. Logs contain codes/non-sensitive identifiers only. Failure cannot block/alter Accept/Reject. Token refresh retry is once per auth failure, durable retries bounded by event TTL. Authentication, authorization, permission and old-client acceptance evidence each need isolated/phone tests; none is claimed fixed.
