## Exact Windows steps — production AAB

### 1. Prepare tools and source

1. Update your local project from the connected GitHub repository to include this handoff. Keep the existing package, `google-services.json` and original upload key; **do not create a replacement key**.
2. Install Node.js LTS and Android Studio. In **SDK Manager**, install Android SDK Platform **36**, the corresponding build tools and Android SDK command-line tools; accept SDK licences.
3. Install JDK **21**. In Android Studio **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK**, select it. Set Windows `JAVA_HOME` to that JDK and add its `bin` to PATH for terminal commands. Restart the terminal; verify `java -version` and `javac -version` show 21.
4. Confirm in Play Console's production/internal/closed/open tracks and uploaded drafts that 104 is unused and greater than the highest uploaded code. Do not change 10.0.04/104 here.

### 2. Build web and sync (PowerShell, project root)

Run each command separately, and stop on a nonzero exit code:

```powershell
npm ci
npm run build
Test-Path .\dist\index.html
Get-ChildItem .\dist\assets
npx cap sync android
npm run android:verify-permissions
```

`Test-Path` must return **True**, the assets listing must contain generated JS/CSS, and build/sync/check must all succeed. Use `npm install` only if `npm ci` identifies a genuine lockfile/dependency mismatch; investigate the error and preserve Capacitor v7 rather than using `--force`. No dependency reinstall was required here.

Do not run sync if build fails. Do not substitute the older `android/app/src/main/assets/public` as build output. The verifier must report parity with dist and all required markers before continuing.

### 3. Run tests and open Android Studio

```powershell
npm test
npx cap open android
```

In Android Studio let Gradle sync finish, with JDK 21 selected. In its terminal (directory `android`):

```powershell
.\gradlew.bat testDebugUnitTest
```

Inspect `app/build.gradle`: applicationId **app.didisnow.worker**, versionName **10.0.04**, versionCode **104**, target/compile SDK **36**. Confirm the Firebase client package still matches. Optional Git Bash source release guard: `bash scripts/android-release-check.sh <confirmed-highest-uploaded-code>` (use 102 only if highest across every track).

### 4. Generate signed bundle with the existing upload identity

1. Choose **Build → Generate Signed Bundle / APK… → Android App Bundle → Next**.
2. Select module **app**, the existing upload keystore, its existing alias and passwords locally. Do not paste credentials into chat or commit them.
3. Select **release** and the desired output folder; finish generation. Record the **actual** output path from Android Studio. A direct Gradle `bundleRelease` normally uses `android/app/build/outputs/bundle/release/app-release.aab`; the wizard may use `android/app/release/app-release.aab` or your chosen folder.

For a repeatable Gradle build instead of the wizard, place an ignored `android/keystore.properties` locally:

```properties
storeFile=C:/private-keys/existing-upload-key.jks
storePassword=<your local keystore password>
keyAlias=<your existing upload alias>
keyPassword=<your local key password>
```

Confirm Git ignores this file (`git check-ignore android/keystore.properties`); do not stage it. Paths are examples, not provided credentials. From `android`, run `.\gradlew.bat clean bundleRelease` only after successful web build/sync/checks. Without external signing configuration, this Gradle release may be **unsigned**; never mistake existence for a signed release.

### 5. Verify the generated AAB — required before calling it ready

In PowerShell, substitute the actual generated file path:

```powershell
jarsigner -verify -verbose -certs "C:\actual-output\app-release.aab"
keytool -printcert -jarfile "C:\actual-output\app-release.aab"
Get-FileHash "C:\actual-output\app-release.aab" -Algorithm SHA256
```

Require `jar verified`, investigate all warnings, and compare the signer SHA-256 with **Play Console → App integrity → Upload key certificate**, not the separate Google-managed app-signing certificate. Do not print keystore passwords.

Using Google's official bundletool JAR downloaded locally:

```powershell
java -jar "C:\tools\bundletool-all.jar" validate --bundle="C:\actual-output\app-release.aab"
java -jar "C:\tools\bundletool-all.jar" dump manifest --bundle="C:\actual-output\app-release.aab" --module=base
```

Require validation success; manifest must show package **app.didisnow.worker**, versionName **10.0.04**, versionCode **104**, SDK 36 and expected notification services/permissions. Open the AAB as a ZIP or use Android Studio's analyzer and verify `base/assets/public` carries the freshly synced JS/CSS, approval/notification/Start OTP features, and Capacitor plugins/configuration (no remote preview server). Firebase merged resources/native integration must be present.
